# 오름 기능명세서

> 작성일 2026-11-14 · 버전 0.3 · 대상 코드: `oreum-app/` (React 화면), `data/rules.json` (규칙), `rules.py` (분석), `pipeline/` (AI 변환)

---

## 1. 시스템 구성

```
브라우저 (서버 없음)
 oreum-app/  React 앱 (권장, Vercel 배포 대상)
  ├─ /            시뮬레이터 (pages/Simulator.jsx)
  ├─ /analysis    데이터 분석 (pages/Analysis.jsx)
  ├─ /review      AI 검수 화면 (pages/Review.jsx)
  ├─ src/lib/engine.js     판정 엔진 (JavaScript)
  └─ public/data/          rules.json, review.json (빌드 시 자동 복사)

data/rules.json       규칙·금액·근거 ◀── rules.py (파이썬 분석)도 같은 파일을 읽음
pipeline/             원문 → AI 변환 → 채점 → 검수용 JSON (파이썬)
tests/                JS·파이썬 엔진 일치 검사 (GitHub Actions에서 PR마다 실행)
외부 라이브러리: React 18.3.1, react-router-dom 6.28.0, Chart.js 4.4.1, Vite 5.4.11
```

## 3. 기능 상세

### F-01. 가구 정보 입력
| 항목 | 입력 형식 | 범위·기본값 | 비고 |
|---|---|---|---|
| 거주 지역 | 선택 | 대구광역시 북구 / 경상북도 경산시 | `rules.json`의 `regions` |
| 본인 나이 | 숫자 | 19~100, 40 | 65세 이상이면 노인 |
| 배우자 있음 | 체크 | 해제 | |
| 배우자도 65세 이상 | 체크 | 배우자 있을 때만 활성 | |
| 맞벌이 | 체크 | 배우자 있을 때만 활성 | 근로장려금 유형 결정 |
| 자녀 수 | 숫자 4칸 | 영유아·초·중·고 각 0~5 | |
| 올해 태어난 아이 | 체크 + 출생 순위 | 첫째~넷째 이상 | 체크 시 영유아 0명이면 1명으로 자동 변경 |
| 장애인 가구원 / 한부모 / 셋째 이상(7~18세) | 체크 | 해제 | |
| 본인이 심한 장애 | 체크 | 해제 | 장애인연금 (18~64세) |
| 재산 (선택) | 숫자 3칸 (만 원) | 주택·전세보증금, 예금·적금, 부채. 기본 0 | 재산의 소득환산액을 소득인정액에 더함, 장려금 재산 요건 판정 |
| 거주 기간 | 숫자 (개월) | 0~600, 60 | 다자녀가정 지원 판정 |
| 감면·현물 환산 | 토글 | 켜짐 | 합계에 포함 여부 |

- **처리:** 입력이 바뀔 때마다 즉시 다시 계산. 예시 가구 선택 표시는 해제.
- **가구원 수:** 1 + 배우자 + 자녀 수 (최대 6명으로 계산)

### F-02. 예시 가구
| 버튼 | 입력값 | 시작 소득 |
|---|---|---|
| 한부모 + 자녀 2명 | 경산, 38세, 한부모, 초1·중1 | 300만 원 (첫 화면 기본값) |
| 1인 청년 | 경산, 29세 | 100만 원 |
| 어르신 단독 | 대구 북구, 70세 | 60만 원 |
| 4인 가구 | 경산, 36세, 배우자, 영유아1·초1 | 250만 원 |

### F-03. 소득 슬라이더
- 범위: 0원 ~ 가구원 수별 기준중위소득 100% (1만 원 반올림), 1만 원 단위
- 가구 구성이 바뀌면 최댓값을 다시 계산하고 현재 값이 넘으면 최댓값으로 맞춤

### F-04. 숫자 카드
| 카드 | 계산 |
|---|---|
| 월 근로소득 | 슬라이더 값 |
| 받는 혜택 (월) | 현금 혜택 합 (+ 토글 켜짐 시 감면·현물 혜택) |
| 근로소득 + 혜택 | 위 두 값의 합 |
| 기준중위소득 대비 | 근로소득 ÷ 중위소득 × 100 |

### F-05. 절벽 그래프
- X축: 월 근로소득 (50만 원마다 눈금), Y축: 월 금액
- 누적 영역: 근로소득(회색) + 혜택별 색상
- 굵은 선: 근로소득 + 혜택 합계
- 세로선: 절벽(빨간 점선), 현재 소득(파란 실선)
- 마우스 오버: 해당 소득의 혜택별 금액 (0원 항목 숨김)

### F-06. 다음 절벽 알림
- 현재 소득보다 큰 첫 번째 절벽을 찾아 표시
- 문구: "월 소득이 {절벽 소득}이 되면 {손해액} 손해" + "지금보다 {차이} 더 벌면…" + 사라지는 혜택 칩
- 절벽이 없으면 초록 안내: "이 소득 이후로는 절벽이 없습니다"

### F-07. 받는 혜택 탭
- 열: 혜택(중앙/지자체 태그), 종류(현금/감면·현물/자격·융자), 월 환산액(융자는 '자격'), 근거

### F-08. 절벽 목록 탭
- 열: 월 소득, 중위소득 대비 %, 손해액, 사라지는 혜택

### F-09. 지역 비교 탭
- 같은 가구를 모든 지역에 넣어 근로소득+혜택 그래프를 겹쳐 그림
- 지역별 현재 소득 기준 혜택 합계와 목록
- 셋째 이상 자녀 + 거주 36개월 미만이면 경고: "경산시 다자녀가정 지원은 3년 이상 거주… {남은 개월} 더 필요"

### F-10. 자립 경로 탭
- 자산형성 지원, 근로소득공제, 자활사업, 이행 급여·유예 제도 안내 (정적 문구)

### F-11. 푸터
- 데이터 출처, 참고용 안내, 계산 가정(`assumptions`), 판정 규칙 표(`rule_table`)

## 4. 판정 로직

### 4.1 기준값
- 기준중위소득(월) = 생계급여 선정기준(중위 32%) ÷ 0.32 (주거급여 48% 표와 일치 확인)
- 소득인정액 = (근로소득 − 추가공제) × 0.7 + 재산의 소득환산액 + 기초연금 + 장애인연금 기초급여
- 재산의 소득환산액 (기초생활보장·한부모): (재산 − 기본재산액 − 부채) × 월 환산율 (주거용 1.04%, 한도 초과분 4.17%, 금융 6.26%, 금융재산 생활준비금 500만 원). 기본재산액 대구 북구 7,700만·경산 5,300만 원
- 기초연금·장애인연금: (주거용 − 기본재산 공제(대구 북구 1억3,500만·경산 8,500만) + 금융 − 2,000만 − 부채) × 연 4% ÷ 12
- 근로·자녀장려금: 재산 합계 2억4천만 원 이상 제외, 1억7천만 원 초과 50%
- 근로소득공제 (2026 사업안내): 만 34세 이하 월 60만 원, 65세 이상·장애인 월 20만 원을 먼저 뺀 뒤 30% 공제 (일반은 30%만)
- 금액별 근거와 확인 상태: `rules.json`의 `verification`

### 4.2 급여별 판정
| 급여 | 자격 | 월 금액 | 종류 |
|---|---|---|---|
| 기초연금 | 65세+ & 0.7 × max(0, 근로소득 − 116만) ≤ 선정기준액(단독 247만/부부 395.2만) | 기준연금액 (부부 동시 수급 시 각 20% 감액) | 현금 |
| 생계급여 | 소득인정액 < 중위 32% | 중위 32% − 소득인정액 | 현금 |
| 의료급여 | 소득인정액 ≤ 중위 40% | 환산 가치 × 가구원 수 | 현물 |
| 주거급여 | 소득인정액 ≤ 중위 48% | 기준임대료(급지·가구원) − 30% × max(0, 소득인정액 − 중위 32%) | 현금 |
| 교육급여 | 소득인정액 ≤ 중위 50% & 학생 자녀 | 학교급별 연액 ÷ 12 | 현금 |
| 에너지바우처 | 수급자 & (노인·영유아·장애인·한부모·자녀 2명+) | 가구원 수별 연액 ÷ 12 | 현물 |
| 통신비 감면 | 생계·의료 수급자 → 상위 금액 / 그 외 수급자·차상위·기초연금·장애인 → 하위 금액 | 정액 | 현물 |
| 근로장려금 | 연 총소득 구간 (단독/홑벌이/맞벌이) | 증가–평탄–감소 구간 연액 ÷ 12 | 현금 |
| 자녀장려금 | 자녀 있음 & 홑벌이·맞벌이 & 연 총소득 < 7,000만 | 자녀당 최대액, 구간 이후 50%까지 감소 | 현금 |
| 한부모 아동양육비 | 한부모 & 자녀 & 근로소득×0.7 ≤ 중위 65% | 자녀 1인당 월 23만 원 | 현금 |
| 장애인연금 | 본인 심한 장애 & 18~64세 & 0.7 × max(0, 근로소득 − 116만) ≤ 단독 140만/부부 224만 | 기초급여 349,700원 + 부가급여 (수급자 9만/차상위 7만/그 외 3만, 추정) | 현금 |
| 문화누리카드 | 수급자 또는 차상위 | 6세 이상 가구원(본인·배우자·초중고 자녀) × 연 15만 원 ÷ 12 | 현물 |
| 경산 진료비 감면 | 경산 & 65세+ | 환산 가치 × 노인 수 | 현물 |
| 경산 출산장려금 | 경산 & 올해 출생 | 출생 순위별 월 10/20/30/50만 원 | 현금 |
| 경산 생활안정자금 | 경산 & 생계·의료·주거 수급자 | 융자 자격 (최대 1,200만 원) | 자격 |
| 경산 다자녀가정 지원 | 경산 & 셋째 이상 7~18세 & 거주 36개월+ | 연 50만 원 ÷ 12 (7~15세 기준) | 현금 |
| 북구 건강보험료지원 | 북구 & 의료급여 아님 & 노인·장애인·한부모 & 추정 보험료 ≤ 최저보험료 | 월 22,809원 (최저보험료 + 장기요양, 조례) | 현물 |

- **수급자** = 생계·의료·주거·교육급여 중 하나 이상 자격
- **차상위(근사)** = 비수급 & 소득인정액 ≤ 중위 50%

### 4.3 시뮬레이션과 절벽 탐지
1. 소득 0원부터 중위소득 100%까지 1만 원 단위로 판정을 반복한다.
2. 각 소득에서 `근로소득 + 혜택 합계`를 계산한다.
3. 직전 단계보다 합계가 **1,000원 이상 줄어든** 지점을 절벽으로 기록한다.
4. 직전 단계에는 있었지만 이번 단계에 없는 혜택을 '사라지는 혜택'으로 기록한다.

## 5. 데이터 구조 (`data/rules.json`)
| 키 | 내용 | 예시 |
|---|---|---|
| `year` | 기준연도 | 2026 |
| `lines.saeng_32` / `lines.jugeo_48` | 가구원 수별 선정기준 (원/월) | `"1": 820556` |
| `params.*` | 금액·비율 파라미터 | `edu_annual.elem: 502000` |
| `provisional` | 추정값 목록 | `["gs_clinic_value", …]` |
| `verification` | 항목별 값·확인 상태·근거 | `"munhwa": {status: "확인(공식)"}` |
| `analysis_households` | 분석용 대표 가구 6개 | |
| `regions` | 지역별 급지·시도 | `"경상북도 경산시": {"rent_grade": "4급지(그 외 지역)"}` |
| `rule_table` | 화면 표시용 판정 규칙 요약 | `{service, provider, condition, status, amount}` |
| `assumptions` | 계산 가정 문구 | |

**수정 규칙**
- 금액 변경 → `rules.json`만 수정, `provisional`에서 해당 키 삭제
- 계산 방식 변경 → `oreum-app/src/lib/engine.js`, `rules.py`를 함께 수정 후 `python tests/parity_py.py && node tests/parity.mjs`
- 지역 추가 → `regions`에 추가 + 엔진의 지자체 혜택 분기 추가

## 7. AI 변환 파이프라인 (`pipeline/`)
| 단계 | 파일 | 내용 |
|---|---|---|
| 수집 | `fetch_bokjiro.py`, `collected/` | 공공데이터포털 복지서비스 API(예정) 또는 복지로 상세 페이지에서 원문 수집 → `raw/*.txt` |
| 변환 | `convert.py` | GPT-5(OpenAI) 또는 Claude에 원문 + 프롬프트를 보내 JSON Schema 구조화 출력으로 규칙 생성. 조건마다 근거 인용 |
| 채점 | `evaluate.py` | 정답(`gold/`)과 비교: 서비스 정확도, 조건 재현율·정밀도, 판정 가능 여부, 근거 인용 일치, 금액 |
| 검수 | `export_review.py` → React `/review` | 원문과 AI 규칙을 나란히 보고 승인·수정·삭제, JSON 내보내기 |

- 규칙 형식(`schema.py`): `judgeable`, `conditions[{field, op, value, group, evidence}]`, `benefit{type, monthly_amount_won}`
- 세트: 학습용 13건(`c*`, `l*`), 시험용 1차 14건(`t*`, 경산), 시험용 2차 16건(`n*`, 대구 북구·영천)
- 결과 기록: `pipeline/RESULTS.md`

## 10. 배포
1. GitHub `oreum-welfare/oreum` 저장소의 `main` 브랜치를 배포
2. Vercel → Add New → Project → 저장소 Import
3. **Root Directory: `oreum-app`** (Framework: Vite, Build `npm run build`, Output `dist`)
4. Deploy → `프로젝트이름.vercel.app`
5. 이후 main에 합칠 때마다 자동 재배포
