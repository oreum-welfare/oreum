# 오름 PRD (제품 요구사항 문서)

> 작성일 2026-11-14 · 버전 0.3 · 상태: 프로토타입 완성, AI 파이프라인 시험 중

---

## 1. 제품 개요
| 항목 | 내용 |
|---|---|
| 제품명 | 오름 |
| 형태 | 웹 서비스 (브라우저에서 사용, 설치 불필요, 모바일 대응) |
| 구성 | React 앱 (시뮬레이터 · 데이터 분석 · AI 검수) + AI 변환 파이프라인 (파이썬) |
| 배포 | Vercel (정적 웹, 서버 없음) |
| 한 줄 정의 | 소득이 바뀔 때 받는 복지 혜택의 변화를 계산해 복지 절벽을 찾아 주는 시뮬레이터 |

## 2. 목표

### 2.1 제품 목표
1. 사용자가 **1분 안에** 자기 가구의 복지 절벽 위치와 손해 금액을 확인할 수 있다.
2. 절벽마다 **끊기는 혜택**과 **근거(선정기준·출처)**를 함께 보여 준다.
3. 같은 가구를 **지역별로 비교**할 수 있다.
4. 새 지역의 혜택을 **AI 변환 + 사람 검수**로 추가할 수 있다.

### 2.2 마일스톤
| 시점 | 목표 |
|---|---|
| 11/17 | 중간 발표 시연 (예시 가구 → 슬라이더 → 절벽 → 지역 비교), 배포 URL |
| 11/20 | 공모전 제안서 제출 |
| 11/24 | 데이터 분석·AI 결과 반영, 시연 영상 |
| 12/3 | 본선 진출 시 AI 변환 → 검수 → 반영 흐름 시연 |

### 2.3 성공 지표
| 지표 | 목표값 | 현재 (11/14) |
|---|---|---|
| 반영 제도 수 | 15개 이상 | **17개** (중앙 12, 지자체 5) |
| 추정값 수 | 최소화, 모두 '추정' 표시 | 3개 (표시 완료) |
| JS·파이썬 엔진 계산 일치 | 100% | **100%** (테스트 가구 14개, CI 자동 검사) |
| AI 변환 정확도: 처음 보는 서비스 | 측정·공개 | 2차 36% (경산 14건) → 3차 〔결과〕 (대구 북구·영천 16건) |
| AI가 지어낸 조건 | 0건 | **0건** (모든 단계) |
| AI 근거 인용 일치 | 100% | **100%** |
| 시연 소요 시간 | 1분 30초 이내 | 리허설 예정 |

## 3. 범위

### 3.1 포함 (v0.x)
- 지역 2곳: 대구광역시 북구, 경상북도 경산시
- 중앙 12종: 생계·의료·주거·교육급여, 기초연금, 장애인연금, 한부모 아동양육비, 에너지바우처, 문화누리카드, 이동통신요금 감면, 근로장려금, 자녀장려금
- 지자체 5종: 경산 65세 이상 진료비 감면·출산장려금·생활안정자금·다자녀가정 지원, 대구 북구 건강보험료지원
- 입력: 지역, 나이, 배우자, 자녀(학교급별), 신생아, 장애인 가구원, 본인 심한 장애, 한부모, 거주 기간, 월 근로소득
- AI 파이프라인: 원문 수집, 규칙 변환, 정답 비교 채점, 검수 화면

### 3.2 제외 (향후 확장)
- 재산 입력, 부양의무자 기준
- 근로소득 외 소득 (사업·연금·재산 소득)
- 전국 시군구 확대 (API + AI 변환으로 단계적 확대)
- 검수 결과의 규칙 파일 자동 반영 (현재는 사람이 반영)
- 회원가입, 상담 기록 저장, 행복이음 연계

## 4. 사용자 시나리오

### 시나리오 A. 사례관리자 상담 (핵심)
> 경산시 자활센터 상담사가 한부모 어머니(초·중학생 자녀 2명, 월 300만 원)와 상담한다.
1. '한부모 + 자녀 2명' 예시를 고르고 소득을 300만 원으로 맞춘다.
2. 다음 절벽 알림: "월 307만 원이 되면 의료급여가 끊겨 월 143,654원 손해".
3. 슬라이더를 383만 원까지 올리자 교육급여·문화누리카드·에너지바우처·통신비가 동시에 끊기는 것이 보인다.
4. 자립 경로 탭에서 자산형성 지원 제도를 함께 안내한다.

### 시나리오 B. 수급자 본인 확인
> 1인 청년이 일자리 제안을 받고 실제로 이득인지 확인한다.

### 시나리오 C. 정책 담당자 검토
> 지자체 담당자가 데이터 분석 화면에서 가구 유형별로 절벽이 몰리는 구간(중위 70~75%)을 확인한다.

### 시나리오 D. 규칙 검수자
> 새 지자체 서비스를 AI가 변환한 결과를 검수 화면에서 원문과 대조해 승인·수정한다.

## 6. 비기능 요구사항
| ID | 요구사항 |
|---|---|
| NFR-01 | **정확성:** JS(React)·파이썬 엔진 결과가 일치해야 한다 (오차 0.01원 미만). PR마다 CI가 검사한다. |
| NFR-02 | **단일 데이터 원천:** 규칙과 금액은 `rules.json` 한 파일에서만 관리한다. |
| NFR-03 | **성능:** 슬라이더 조작 시 화면이 즉시 갱신된다. |
| NFR-04 | **반응형:** 375px 휴대폰 화면에서 가로 스크롤 없이 사용 가능하다. |
| NFR-05 | **가용성:** 서버 없이 정적 배포한다. |
| NFR-06 | **개인정보:** 입력값을 서버로 보내거나 저장하지 않는다 (브라우저 안에서만 계산). |
| NFR-07 | **투명성:** 모든 혜택에 근거를 표시하고, 추정값은 '추정'으로 밝힌다. |
| NFR-08 | **AI 평가의 공정성:** 시험용 정답은 AI 결과를 보기 전에 작성하고, 결과를 본 뒤 고치지 않는다. 프롬프트 개선에 쓴 세트는 시험용으로 쓰지 않는다. |

## 7. 가정과 제약
- 재산 0원, 부양의무자 기준 미적용
- 소득인정액 = (근로소득 − 추가공제) × 0.7 + 기초연금 + 장애인연금 기초급여 (추가공제: 34세 이하 60만, 65세 이상·장애인 20만 원)
- 주거급여는 임차가구, 실제 임차료 ≥ 기준임대료 가정
- 차상위 = 비수급 + 소득인정액 ≤ 중위 50%로 근사
- 근로·자녀장려금은 전년도 소득 기준 지급이지만 같은 해 월 환산으로 표시
- **참고용이며 실제 수급 판정이 아님**

## 8. 리스크와 대응
| 리스크 | 영향 | 대응 |
|---|---|---|
| 추정값이 실제와 다름 | 손해 금액 오차 | 추정 표시, 사업안내·통계로 교체 |
| "소득을 줄이라는 거냐" 질문 | 취지 오해 | 자립 경로 안내, 사례관리자 도구로 포지셔닝 |
| 미국 CLIFF와 유사 | 독창성 감점 | 먼저 언급하고 차별점(한국 제도·시군구, AI 변환, 자격 연쇄) 제시 |
| AI 정확도가 낮게 나옴 | AI 혁신성 감점 | 정직하게 공개하고, 오류 유형 분석과 사람 검수 설계를 강점으로 제시 |
| 공공데이터포털 API 연동 지연 | 자동 수집 시연 불가 | 복지로에서 수집한 원문 43건으로 대체 시연 |
| 발표 중 인터넷 장애 | 시연 실패 | 백업 영상 준비 |
| 복지 기준 변경 | 계산 오류 | 기준연도 표시, `rules.json`만 수정 |
